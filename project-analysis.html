What's already done

The architecture is good. Most of what's missing is wiring and finishing, not redesign.

Infrastructure

  • Compose with Kafka + ZooKeeper, Redis (AOF), Postgres 16, healthchecks and depends_on: service_healthy
  • Kafka, Redis and Postgres exporters
  • Multi-stage Dockerfiles per service

Observability

  • Alloy scrapes all services and remote-writes to Prometheus
  • Alloy tails /logs/*.log into Loki
  • Alert rules: availability, p99 latency, error rate, business, infra
  • prom-client registries with HTTP + business metrics (driver, ride, notification)

Gateway + Auth

  • JWT middleware with public-route list
  • Register / login with bcrypt + signed JWT
  • Gateway proxies auth + drivers via HttpService
  • Global ValidationPipe with whitelist

Driver + Ride domain

  • Driver status + location, Redis GEOADD/ZREM pool
  • Ride request → ride.requested, status updates, history by rider
  • QueryRunner migrations with indexes for auth, driver, rider, ride

Matching + Notification

  • Matching claims the nearest driver atomically: one Lua script runs GEOSEARCH + ZREM, so two rides can't get the same driver
  • Matching + notification metrics exported on /metrics, incl. ride_matching_duration_seconds for the existing alert
  • Socket.io Redis adapter via a RedisIoAdapter, per-user rooms, connection gauge that can't go negative
  • Consumers start after handlers register; notification skips + counts events with no recipient

Driver busy lifecycle

  • driver.assigned → BUSY, so location pings no longer re-add a driving driver to the pool
  • ride.completed / cancelled → back to AVAILABLE at the last position (OFFLINE if the photo was removed)
  • BUSY is system-owned: manual busy → 422, any manual change mid-ride → 409

Profile photos (Floci S3)

  • Floci in compose, bucket fake-bolt-profile-photos created by an idempotent hook
  • auth owns users.photo_key: presigned PUT, confirm, delete, GET /users/me
  • Drivers can't go available without a photo (422), riders optional
  • user.photo.updated keeps drivers.has_photo in sync; photo removed while online forces offline
  • Gateway /users/me/* forwards x-user-id from the JWT and passes real status codes through

Docker images (pnpm)

  • pnpm 10.34.8 everywhere via packageManager + corepack; npm lockfiles removed
  • 3-stage node:22-alpine build, prod deps only, BuildKit pnpm cache, USER node
  • CMD node dist/src/main.js (root orm.ts puts the build in dist/src, verified)
  • .dockerignore per service; bcrypt 6 with prebuilt Alpine binaries
  • Prod deps: 43 MB (matching) to 160 MB (auth), images ~200–320 MB estimated

Boot fixes

  • orm.ts uses DATABASE_URL, runs migrations on boot, logs to the console
  • postgres/init creates every service database; migrations no longer call createDatabase and rethrow on failure
  • Entity properties mapped to the snake_case columns the migrations create
  • All 9 services listen on PORT; restart: on-failure covers the plain depends_on
  • Fixed DI crashes in auth (JWT/metrics), ride (Config/metrics), rider (Config); every service passes a Nest preview check
  • Seed reads the user id from the JWT and waits for the services; root .env generated locally

Ride receipts (email-service)

  • Consumes ride.completed, emails the rider through SES on Floci
  • sent_emails log with a ride snapshot, unique per ride, retries on failure
  • Doubles as ride history: GET /users/me/receipts
  • Metrics + alerts, scraped by Alloy; k6 checks every receipt

k6 load test

  • Custom image with xk6-socket.io v0.1.0, runs last and exits
  • Photo rules (no photo, 6 MB, PDF, fake PNG), full ride flow, BUSY guard, receipts
  • Custom counters/trends/rates with tags, PASSED/FAILED business summary

Seed

  • 100 drivers + 200 riders with Tallinn coordinates through the real APIs
